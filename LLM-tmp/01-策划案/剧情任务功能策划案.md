# 《檐下千秋》剧情任务功能策划案

版本：2026-09-12，内容协议 v7。当前实现入口为 `客户端/project.godot`。本文与《剧情任务与对话脚本》共同更新旧草稿中的剧情、任务、账号与拓印资产约定；原始稿件保留作过程记录。

## 游戏定位

一款以古建记忆为线索的单人国风解谜冒险。玩家在风雨廊桥醒来，手中有一本空白《檐下谱》。通过调查、描摹、构件归位与守护，找回建筑背后的人间故事，最终理解白蚀为何产生，并把续写记忆的权利交还给后来的人。

本轮重点为剧情任务与对话演出。目标体验时长约 25–40 分钟，需通过真人试玩校准。序章承担教学，社庙建立情感，戏楼提出“不完美是否值得保存”，牌坊追问“谁被允许留名”，墨塔完成因果揭示。

## 核心循环与任务进度

地图当前任务 → 角色对话 → 三处线索调查 → 修复谜题 → 墨灵显影 → 保留或以旧换新 → 守护战（部分任务）→ 结语与下一任务。

章节按事件顺序解锁。剧情推进不消耗墨痕，避免玩家因重试后资源不足而看不到后续故事。墨痕保留用于失败回溯；序章在墨痕不足时可免费重试。已拓印的记忆和已学技能不因战斗失败消失。

| 篇章 | 剧情任务 | 玩法与叙事目的 |
|---|---|---|
| 序章·廊桥 | 桥上平安 | 首次对话、调查与描摹；记住等待归来的人；学习斗拱 |
| 社庙 | 香火断、檐下客、社鼓声 | 归位、补字、净化；由合力修梁走向接纳陌生人和共同节庆；学习藻井 |
| 戏楼 | 开场锣、名角儿 | 行头辨认、描摹、台步与布景归位；保存尚未完美的传承；学习飞檐 |
| 牌坊 | 四柱三间、无名匠 | 规制辨认、构件归位、技能组合；让无名工匠的劳动被看见 |
| 墨塔 | 登塔、千层墨 | 综合修复与守护；追溯初代抹除记忆的代价；选择把什么交给后来的人 |

## 对话与任务功能

每个任务包含六句开场对话、三条调查线索、保留回应、遗忘回应与完成结语。带战斗的任务增加守护前台词。共 60 句开场对话、30 条调查线索。角色以“拓印师”“廊桥”“社庙”等具名发言；客声、童声、匠人回声均是古建存留的记忆。

对话支持上一句、下一句、跳过、返回和阅读位置保存。回到地图再进入同一任务时，恢复正在阅读的句子；读完或跳过后从开头重新回看。跳过不跳过调查、谜题、取舍或战斗。剧情文本无阅读倒计时。

地图顶部与底部“剧情 · 任务”页呈现当前任务目标。完成任务后加入剧情回顾，按篇章顺序列出；回顾展示开场、结语、实际发生的遗忘回应与终章选择，不能重新领取奖励，也不能改写已经确认的选择。查看图录、设置、剧情册时暂停当前描摹和战斗。

调查点由任务数据提供，玩家靠近或点击调查。每条线索解释一个场景物件与相关修复动作：例如供桌残纸提示“宁”，戏单与水袖提示“旦”，石柱与开间提示“四柱三间”。不得只显示调查点名称而不给剧情信息。

## 拓印与心舍

墨线拓印保留逐笔手绘操作，支持查看起收笔、容差提示与单笔重描。最终收藏图采用提前生成并打包的 PNG；显影、图录、对照、结算与墨灵详情引用同一稳定图片路径。游戏运行时不请求生图 API，不根据轨迹生成收藏图，也不靠实时几何绘制伪造拓印成品。

10 道墨灵各有独立构图和主题：廊桥归来、斗拱承香、檐下分饭、社鼓回春、戏楼行腔、师徒绝唱、四柱三间、匠人双手、墨塔初代、留白续谱。原图与完整提示词放在 `output/imagegen/`，运行素材放在 `客户端/assets/rubbings/`。

### 静态美术与生图记录

拓印收藏图在发布前离线生成并打包为 PNG，运行时只读取静态文件。已使用 DashScope `qwen-image-3.0-pro` 生成十张独立构图，调用地址为 `https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation`（兼容模型列表地址为 `https://dashscope.aliyuncs.com/compatible-mode/v1`）。运行时不请求 API，也不把生成失败当作玩法依赖；完整提示词、调用记录和重试方式见 `output/imagegen/生成记录.md`。密钥只允许通过进程环境注入生成脚本，禁止提交到仓库、存档或发布包。

心舍初始五格，社庙章末扩为六格，牌坊章末扩为七格。全篇十道记忆会产生有限容量下的真实取舍。抹去旧记忆须确认；色调与回声随之褪去，技艺保留，账册记录“在何时、为何替换”。新台词目前以文字呈现，原有音频继续朗读记忆摘要。

## 结局设计

终章不是只有一个标准答案的知识题。三种选择均同分并完成游戏：传下修复的方法、留下所有取舍的记录、留白让后来人续写。三条后日谈分别落到工坊学徒、带批注的记忆册和孩子新画的小棚。玩家首次确认的回答持久保存；重连、重试和回顾均不能覆盖它。

保留记忆与遗忘记忆影响个人回声和账册，而非宣称一条道路必然正确。故事强调真实记录与承认缺口，不替无名匠人编造名字，不将未经证实的补白当作历史。

## 入口、存档与维护

打开游戏后直接进入地图，不再注册、登录、输密码或领取登录令牌。配套 Go 程序仅负责本地游戏规则和 JSON 存档。新玩家建立固定本地进度；旧版存档首次使用时选择最近更新的一份玩家进度，其余旧记录完整保留。旧账号字段仅作原样兼容数据保留，不再参与任何认证。

任务剧情与图片路径统一维护在 `服务端/content/chapters.json`。公开目录带上调查点、对话、线索和墨灵图路径；知识谜题答案不下发，终章选项是公开的叙事选择。服务启动时验证对话完整性、调查线索数量、记忆来源和静态图片路径格式。

## 验收标准

- 无账号可直接游玩；重启后保留已完成任务与当前未完成事件。
- 十个任务全部可达，任务按钮按剧情次序开放。
- 对话上一句、下一句、跳过、续读和回顾均可使用。
- 调查呈现三条实质线索；解谜答案可从剧情推得。
- 查看剧情册和心舍不丢失描摹、不消耗战斗时间。
- 五章均能按真实技能冷却与伤害完成，结尾三个回答等价有效。
- 10 张图片各自绑定一个墨灵；图片缺失明确显示“待装裱”，不伪称已生成。
- 客户端、源码、存档和发布包不包含生图密钥；生成脚本从进程环境读取。
