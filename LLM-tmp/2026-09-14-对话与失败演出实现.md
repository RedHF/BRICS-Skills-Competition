# 对话与失败演出实现记录

2026-09-14，内容协议 v9，结算规则仍为 v2。依据本次更新的开发策划及叙事脚本实现，新增台词按原文接入。

## 当前行为

- 开场与剧情回顾采用全屏背景、画面淡入、台词淡入与逐字显现。点击背景、台词或窗口空白直接前进一条，不需要先点一次补全文字；空格/回车同样推进。底部文字入口保留上一句、跳过与返回，这三个入口只执行各自操作。画面拦截输入，避免同时触发底层地图或战斗按钮。
- 事件失败后进入〈失败结局 · 飞鸟山〉。四种已知失败原因各使用脚本规定的首句，其他原因使用默认首句；后八句相同。第九句结束后才显示原有回溯及地图入口，演出期间不提供跳过。回溯费用及记忆保留规则不变。
- 失败阅读进度以会话 ID 和重试次数为键保存在原剧情阅读配置中：同一次失败未看完可续读、看完可直接进入恢复页，回溯后再次失败重新演出。不会修改星级、墨痕、账册或终章回答。
- 戏楼开场锣与名角儿首次通关，在结语下追加对应呓语并逐字呈现。依据首次 `settled` 响应及本地已展示标记判定；重新结算、回顾和已完成任务不重播。

## 数据和代码

`服务端/content/chapters.json` 新增 `failure_scene`（标题、背景、台词、按原因索引的首句）及两个任务的 `story.first_clear_whisper`。公开目录下发这些叙事字段，服务端启动时验证失败脚本完整性。客户端版本检查同步至 v9，需要运行匹配的服务端。

`客户端/scripts/dialogue_stage.gd` 管理演出与窗口输入；`main.gd` 负责阅读进度、失败恢复入口和首次通关触发。原有结算公式和回溯接口保持原规则。

开发策划与叙事的 MD、Word 以及运行说明已同步。Word 使用现有版式生成，经本机 Word 只读导出临时 PDF，再用文档渲染工具逐页检查。

## 制作边界

按叙事脚本允许的占位方式，飞鸟山沿用已有残迹背景；雾中石阶、鸟形剪影和无匾旧亭的独立场景图尚未制作。没有将占位图标作新美术成果。Task01、Task02、Task03、Official_Document 与原发布包保持原样，未执行正式导出、Git 提交或推送。

复现新增专项测试时，先按 [运行说明](剧情版运行说明.md) 启动全新隔离存档服务，再运行：

```powershell
godot --path LLM-tmp/客户端 --audio-driver Dummy --script res://tests/narrative.gd -- --server-url=http://127.0.0.1:8096
```

使用独立 APPDATA，并将 `YANXIA_REVIEW_SHOTS` 设置为已有的截图目录；不要让专项测试与十任务回归共享同一个服务端存档。
