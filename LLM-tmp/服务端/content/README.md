# 内容与墨灵维护

唯一内容源为本目录 `chapters.json`，当前协议版本 3。修改后重启服务端，客户端自动取得公开目录；部署时同步交付目录 `server/content/chapters.json`，不必重新编译客户端文案。

## 对应关系

`memories[墨灵ID]` 定义名称、摘要、技能、容量、来源、记住/遗忘文案、颜色和回声音高。`chapters[].events[].reward.memory_id` 指向墨灵；`memory.source` 必须为同一事件的 `章节ID/事件ID`。`event.story` 保存该事件的 beats、outro，以及可选的 chapter_outro。

新增现有类型的事件：添加墨灵定义，添加对应事件与剧情，再填写 reward.memory_id。加载时会拒绝缺失墨灵、错配来源、缺失剧情和无效拓印线条。不要复用旧 ID 表达另一段记忆，也不要删除已有存档引用的 ID。

玩家持有记录保存取得时的 title、summary、skill、capacity、source 快照；记忆账册保存当时的标题、记住/遗忘行为和作出抉择的事件。客户端用稳定 ID 查找当前目录中的展示文案，账册标题保留历史。已发行墨灵的来源、技能与容量应保持稳定；不同含义或机制使用新 ID，避免让旧存档中的取得快照变义。

技能按钮按已获得墨灵生成；自定义技能名称不需代码登记。新增不同的技能机制仍需要实现相应行为，名称可扩展不代表任意新行为已实现。

## 拓印参数

每个 `kind: trace` 步骤配置 `trace`，不配置字符串答案：

```json
{
  "aspect_ratio": 2.4,
  "tolerance": 0.10,
  "strokes": [ [[0.2,0.3],[0.7,0.3]], [[0.5,0.3],[0.5,0.8]] ]
}
```

坐标范围 0–1，数组顺序就是笔顺；每笔由起点、转折点和终点组成。画布保持 aspect_ratio，服务端按相同比例计算等距容差。tolerance 以画布高度为单位，0.10 对应当前画布约 26 像素的半径，而非细线级精度。客户端显示同一范围的墨带，提交原始采样轨迹，由服务端判定。轨迹摘要写入会话动作记录用于核查。

## 已落实与取舍

初始容量 5 道，每道占 1 格；社庙末扩为 6，戏楼末的草稿配置为 7。社庙檐下客取得藻井，后续社鼓净化才可使用。序章加社庙共四道新记忆，不用虚构初始记忆强迫填满五格；演示允许玩家主动抹除旧记忆。

后续章节保留原始分支选项，标记 draft，暂不开放。待确认的结局、2.5D 场景移动、构件拖拽、永久残迹剧情和墨痕回溯未在本次补写。现有构件谜题仍使用选择按钮，战斗为计时技能交互。`max_attempts` 延续原型配置，统计错误次数，不再把正确步骤消耗为失败次数。
