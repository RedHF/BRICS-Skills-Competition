# 开发与交付说明

本次修改以正式策划案中的序章和完整社庙演示为范围，重点完成拓印描摹与墨灵数据、剧情、展示的一致性。后续章节保留草稿，未虚构待确认结局。

客户端从服务端取得唯一的公开内容目录。墨灵用稳定 ID 与来源事件绑定，记忆账册另记触发抉择的事件。拓印采用分笔鼠标采样，服务端校验方向、顺序、连续性和可见容差带；不接受文字答案代替轨迹。

服务端继续使用 JSON，修复玩家完成事件表复制丢失、会话切片共享及重复请求相关问题。心舍抉择和记忆写入在同一事务发生于战斗前；结算只发放进度奖励，重复结算不重复增加墨痕、容量或账册。网络错误会显示并允许读取服务器状态，不产生本地假结算。

容差按画布高度 10% 计算并固定画布比例，横纵方向使用一致的空间距离；当前显示约 26 像素的容差半径。撤回上一笔不提交服务端，也不增加侵蚀；正式提交失败按原型错误规则处理，但保留画布供修正。

## 构建与检查

```powershell
go -C LLM-tmp/服务端 test ./...
go -C LLM-tmp/服务端 vet ./...
go -C LLM-tmp/服务端 build -trimpath -ldflags '-s -w -H=windowsgui' -o ../交付/檐下千秋-正式版/server/yanxia-server.exe ./cmd/server
godot --headless --path LLM-tmp/客户端 --export-release 'Windows Desktop'
```

Godot 使用 4.5.2，导出预设中的模板路径指向仓库忽略目录 `.tools/godot/templates`；也可在 Godot 编辑器中选择同版本模板。复制服务端内容到交付目录 `server/content/chapters.json`。EXE 已嵌入客户端资源，配套服务端单独保留。

客户端集成测试：先启动一个测试服务，确保 Godot 可执行文件同级 client.cfg 指向该服务，并用隔离 APPDATA 避免污染玩家身份，再执行：

```powershell
godot --headless --path LLM-tmp/客户端 --script res://tests/integration.gd
```

精确需求映射与未纳入本次的原型限制见 `服务端/content/README.md`。
