# 《檐下千秋》原型开发说明

## 本次交付

本目录包含按官方“交互赛道-小游戏”要求搭建的可运行原型框架：

- `客户端/`：Godot 4 客户端。动态 UI 状态机覆盖序章风雨廊桥、第一章社庙三事件，包含文本演出、拓印/选择/构件归位谜题、轻战斗、心舍记忆抉择、星级结算和章节推进。
- `服务端/`：Go 1.22+ 标准库 HTTP 服务。服务器独占玩家存档、会话、记忆账册和结算结果；答案只保存在服务端内容目录。
- `联调脚本/`：PowerShell 冒烟脚本，验证服务端健康、玩家创建、会话、谜题、战斗、选择、结算和重复结算幂等。

原型使用占位色块和文字完成主流程，后续可将美术素材按事件 ID 放入客户端资源目录，不需要改规则代码。

## 运行

### 服务端

```powershell
cd LLM-tmp/服务端
go run ./cmd/server -addr :8090 -content ./content/chapters.json -data ./data/save.json
```

服务端默认监听 `http://127.0.0.1:8090`。`data/save.json` 是服务器端唯一存档，目录已加入忽略规则，正式部署请使用独立持久化路径。

### 客户端

使用 Godot 4.2+ 导入 `LLM-tmp/客户端/project.godot` 并运行。项目设置中的 `yanxia/server_url` 可切换服务端地址。服务端不可用时会明确显示“本地演示模式”，本地状态只留在内存，不会冒充联网存档。

## 联网结算链路

```text
create player -> start session -> submit puzzle steps -> submit battle telemetry
-> submit memory choice -> settle/finish -> server recalculates result and persists
```

客户端只提交步骤 ID、答案、技能时间线和记忆选择。服务端从 `content/chapters.json` 查答案和参数，检查步骤顺序、尝试次数、战斗时长/技能/波次/受击次数、章节解锁和识海容量。客户端不能提交星级、墨痕或奖励数值；`finish` 会按服务器状态重算并用幂等事务写入玩家记录。

## 数据扩展

策划新增章节、事件、谜题步骤、战斗参数、奖励和对白时：

1. 在 `客户端/content/chapters.json` 与 `服务端/content/chapters.json` 同步增加数据。
2. 在 `客户端/content/story_text.json` 增加同名事件的 beats/outro 文本。
3. 如增加新的通用谜题类型，只需扩展客户端展示映射和服务端规则校验；已有事件无需修改。战斗技能按钮和服务端技能校验均读取事件 `required_skills` 与玩家记忆，不需要在代码中登记技能名称。
4. 在目录顶层 `art` 映射中按事件 ID 增加 `backdrop_color` 或 `background` 路径即可替换场景视觉；客户端缺少资源时继续使用占位色，不影响玩法流程。
