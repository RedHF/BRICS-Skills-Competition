# 2026-09-15 全流程可玩性测试与修复

## 结论

五章十任务、八场守护战和三种终章回应通过验证。发现并修复三类可稳定复现的问题；最终客户端专项检查 602 项、零失败。测试使用独立服务端端口和 APPDATA，没有修改玩家真实存档。

环境：Windows、Godot 4.5.2、Go、NVIDIA RTX 4060 Laptop；发行包保持内容协议 v10。

## 修复的问题

| 问题 | 复现 | 修复与验证 |
|---|---|---|
| 探索时主回车、小键盘回车不能调查 | 靠近调查点按回车；原 advance 使用字符值 13，未绑定 Godot 的 Enter 键值；实际窗口输入还复现了逻辑键与物理键不一致 | 调查动作改用逻辑键绑定，包含 KEY_ENTER / KEY_KP_ENTER / 空格；实际窗口依次按键完成三处调查，开发版和发行版另检映射 |
| 调查期间打开设置、心舍等页面后丢失现场 | 调查一处后点击设置，没有“返回当前事件”，从地图重新进入会重置调查进度 | 调查页与修复、战斗页共用暂停恢复；恢复人物位置、已调查点、页面和滚动位置；从设置返回及从地图继续均实点验证 |
| 剧情回顾使用其他任务的背景 | 当前事件为墨塔，在剧情册回顾廊桥 | 回顾按所选事件独立取得背景，不改变当前任务身份；开发版和发行版验证 |

## 测试自身的修正

- 原十任务脚本直接填写拓印数据；本次改为经过 Viewport 的鼠标按下、移动和松开。滚动到画布后等待布局稳定再取坐标，避免测试在布局变化中落笔。
- 完成一道拓印后仍可能处于下一道谜题，诊断依据改为该步骤是否已被服务端接受。
- 原联调脚本直接用战斗夹具覆盖暂停的探索页，本次先恢复该页再切换，消除测试结束时的孤立节点；最终日志无资源泄漏告警。
- 混音取样等待音频线程接入捕获效果后进行，避免将初始化期间的空缓冲误报为无音频。

## 复跑

1. 使用独立 JSON 存档启动服务：`go -C LLM-tmp/服务端 run ./cmd/server -addr 127.0.0.1:18090 -data <独立存档绝对路径>`。
2. 设置独立的 `APPDATA` 和截图目录 `YANXIA_REVIEW_SHOTS`。
3. Godot 调用：`--path LLM-tmp/客户端 --script res://tests/review_journey.gd -- --server-url=http://127.0.0.1:18090`。此脚本从新档完整通关；中断后可以恢复当前未完成步骤。
4. 对通关测试档运行 `tests/playability.gd` 和 `tests/assets_audio.gd`；对各自的新档运行 `tests/narrative.gd` 和 `tests/integration.gd`，同样传入 `--server-url`。
5. 资源检查：`python LLM-tmp/联调脚本/audit_assets.py --output <输出 JSON 路径>`。
