## 需要优先处理的已验证问题

1. **侵蚀与场景没有联动。** 把同一客户端样本的侵蚀设为 0、39、40、69、70、99、100，调用原有状态刷新与地图绘制逻辑；阶段文字会切换，但背景始终 `#14262b`，音频播放器音量始终 `0 dB`。全客户端未发现侵蚀材质、构件崩解或音效失真处理。这里的音量检查只证明属性未变化，没有在本轮测试扬声器。
2. **100 侵蚀后可开新事件，却无法继续正常进度。** 隔离样本从 90 增至 100 后，重新开始同一事件，再提交正确拓印，服务端返回 `accepted=true`、`status=failed`；侵蚀仍为 100，5 点墨痕仍为 5。缺少真正的回溯状态恢复。
3. **事件超时会制造额外惩罚。** 可玩事件统一在开始 240 秒后过期；解谜接口处理过期时直接将玩家侵蚀设为至少 100。隔离样本验证从 0 变成 100。这与单事件 5–8 分钟和心舍暂停的体验目标冲突，且准备战斗仅暂停本地战斗时钟。
4. **战斗时长只有上限。** 输入斗拱 0ms、挥墨 0/500/1000ms，30HP 的序章白蚀被判获胜；30 秒配置没有最低时长约束。这是节奏偏离的证据，不建议仅靠强制等待修补，应一并调整敌人、波次与交互节奏。
5. **记忆保留度未进入结算。** 相同谜题和战斗表现下，keep 与 forget 的结算都为修复度 100、3 星。`calculateResult` 未接收或计算保留数量、保留率或相关权重。

## 应区分的需求变更和策划歧义

- 原稿 §1.6 一度写“拓印新记忆必须抹去旧记忆”，§2.3 明确限定为容量满时。本报告按更明确的核心规则校验，不要求空容量时也强制遗忘。
- 竖屏、拓印容差放宽、标注失败笔画、账号鉴权及开屏 Logo 来自后续用户要求，不能因偏离原稿横屏参考或未写入旧策划案而判为缺陷。
- 描摹错误不增加侵蚀是后来降低描摹挫败感时作出的实现调整；与原稿“解密失败 +10”有差异，应在最终策划案明确例外，不能称为完全一致。
- §2.4 同时写“70–100 进入残迹、记忆永久消散”和“100 时永久消散”，永久性后果发生在 70 还是 100 有歧义。当前两种都未实现，补做时需先统一阈值含义。代码的阶段分界为 40 和 70。
- 三结局数量、官方 IP 映射及 §3.6 的扩展建议仍属待确认；可列为设计待决项，不能靠草稿选项字符串认定功能已完成。

## 验证范围与复核方式

本轮重新运行 `go test ./...`、`go vet ./...`，均通过。通过只说明已有测试满足当前实现，不代表满足策划案全部要求。新增隔离审查使用 Go overlay 注入临时测试，验证高侵蚀重试、过期惩罚、战斗最短输入和星级保留度差异；未向正式存档写入测试账号。Godot 使用原方法的隔离 UI 样本检查七个侵蚀值的背景色、音量属性和阶段名称，没有启动正式游戏流程。

本轮没有重新进行完整人工时长测试、扬声器听感检查或发行 EXE 全流程验收。结论针对当前源代码，不将历史交付说明当作本轮证据。没有给出“完成百分比”，因为一个事件配置、可用按钮与完整场景机制的工作量不同，简单计数会误导。
