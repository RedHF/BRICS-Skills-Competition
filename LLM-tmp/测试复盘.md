以下为历史记录，不代表当前玩法实现。

| 问题 | 复现 | 修改 | 复测 |
|---|---|---|---|
| Godot 首次导入时全局类名未及时解析 | 无头启动提示 `DataRepository`/`NetworkClient` 未声明 | 客户端主脚本改用显式 `preload`，保留可替换模块 | Godot 4.4.1 `--headless --path 客户端 --quit-after 6` 无脚本错误 |
| GDScript 数值推断不稳定 | Godot 解析 `_calculate_stars` 时无法推断 `ratio` | 将比值声明为 `float` 并使用 `maxf` | 同上，无 Parse Error |
| 客户端 settle 与服务端 finish 命名不一致 | 选择后请求 `/settle` 返回 404 | 服务端增加 `settle` 路由别名，客户端保留 `/finish` canonical 调用 | `/settle` 和 `/finish` 均返回 200，重复结算 `already_settled` |
| 记忆选择后未完成最终发奖闭环 | 联网选择成功但 UI 直接显示结算 | 客户端收到 choice 成功后自动请求 settle，服务器返回最终结果 | 联调获得 3 星、3 墨痕、1 条服务器记忆且章节解锁 |
| 答案可能从公开目录泄露 | 检查 `/api/v1/catalog` 响应 | public catalog 省略 puzzle step.answer | Go HTTP 测试断言 JSON 不含 `answer` |
| 服务器失败会话被客户端继续复用 | 谜题尝试耗尽或战斗失败后再次提交旧 `session_id` | 服务端冻结失败会话；客户端清空旧 ID、失效迟到响应并创建新的事件会话 | Godot 无头启动通过；正常 HTTP 冒烟仍完成 3 星结算 |
| 首次连服后“开始调查”仍保持禁用 | 初始 UI 在服务器探测完成前创建 | 探测完成后重绘当前事件，使按钮读取已解析的在线/离线状态 | Godot 无头启动通过，在线/离线入口均可进入 |
| 首屏玩家探测请求被事件重绘取消 | `_ready()` 先发起 `create_player`，随后 `_show_event()` 清理进行中的请求 | 首屏重绘保留 `create_player` 探测令牌，直到响应或超时后再重建入口 | Godot 4.4.1 无头运行通过；服务端联调入口可正常探测 |
| 新章节技能需要修改规则代码 | 战斗按钮和服务端规则曾分别依赖固定技能列表 | 控件读取事件 `required_skills` 与玩家记忆；规则通过服务端传入 `AllowedSkills` 校验归属 | 自定义“木榫”技能 HTTP 流程与规则单测通过 |
| 会话过期后仍可在结算窗口领奖 | 完成选择后手动将会话过期，再调用 `finish` | `choice`/`finish` 统一检查过期时间并将会话持久化为 `failed` | 过期保护 HTTP 单测通过，奖励未写入玩家存档 |
| 在线侧栏重置会覆盖服务器快照 | 在线状态下点击“重新开始本地演示” | 在线时改为“回到序章（保留服务器存档）”；只有离线演示才清空内存 | 客户端状态机无脚本错误，在线存档不会被本地对象替换 |
