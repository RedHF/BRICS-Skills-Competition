# 剧情任务版运行说明

当前源码为内容 v7，直接进入地图，无注册、登录与密码机制。

从仓库根目录启动配套服务：

```powershell
go -C LLM-tmp/服务端 run ./cmd/server
```

再用 Godot 4.5.2 打开 `客户端/project.godot` 并运行。发布版由客户端自动启动同目录的 `server/yanxia-server.exe`，需保留 `server/content/chapters.json`。

地图点击“前往任务”开始逐句对话；上一句、下一句、跳过均在对话页。对话结束后调查三个标记，阅读线索，再开始修复。已完成的故事在底部“剧情 · 任务”中回顾。查看心舍、剧情册和设置时，当前描摹与战斗暂停，点击“返回当前事件”继续。

章节依次开放，无墨痕门票。心舍五格起步，社庙章末六格、牌坊章末七格。容量不足时须选择旧记忆替换并确认；已学技能仍可使用。终章三种回答均可完成，首次确认后保存。

发布版存档为 `%APPDATA%/Godot/app_userdata/檐下千秋/save.json`，对话阅读位置另存 `story-<玩家ID>.cfg`。旧账号字段仅作兼容数据保留，不参与认证；首次使用最近更新的本地玩家进度，之后固定该本地进度。开发服务默认使用 `服务端/data/save.json`，与发布版路径不同。测试使用 `.tools/` 下隔离存档。

如旧服务占用 8090，先退出旧版窗口及服务。客户端会拒绝错误内容版本。可通过 EXE 同级 `client.cfg` 或命令行 `-- --server-url=http://127.0.0.1:8097` 指向另一个本机端口；本版本只连接本机服务。

## 拓印图片生成

使用 `output/imagegen/generate-rubbings.ps1`，从当前进程的 `IMAGE_API_KEY` 环境变量读取密钥。模型列表中对应 `image2.5` 的可用命名为 `gpt-image-2.5`，脚本默认使用该名称，不使用 Python。

```powershell
./output/imagegen/generate-rubbings.ps1 -Force
```

脚本按十个独立提示词生成 PNG，并复制到客户端 `assets/rubbings/`。当前 DashScope 版本使用 `generate-dashscope-rubbings.ps1` 和 `qwen-image-3.0-pro`；生成后重新导入并导出 Godot。游戏本身完全不调用生图接口；缺图时显示“拓印图待装裱”。完整测试和模型切换记录见 `output/imagegen/生成记录.md`。

## 验证

```powershell
go -C LLM-tmp/服务端 test ./...
go -C LLM-tmp/服务端 vet ./...
```

客户端集成测试需独立、全新的本地服务与存档，监听 8097；使用隔离 APPDATA 后运行：

```powershell
godot --headless --path LLM-tmp/客户端 --script res://tests/integration.gd -- --server-url=http://127.0.0.1:8097
```

新对话暂未逐句配音；墨灵详情仍可播放原有摘要回声。后续章节目前以静态拓印图作为叙事背景，非新增完整场景原画。
