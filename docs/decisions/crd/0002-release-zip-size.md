# CRD 0002：更正 T-02 的 DoD 第 7 条（ZIP 小于 100 MiB 这条不可能通过）

- 编号：0002
- 日期：2026-09-28
- 类型：**更正**（不是变更；不移动范围、不加工作）
- 提出人：PM（自己在打包时测量发现）

## 谁提出的

PM。T-02 第一次构建时，服务端编译、Godot 导出和引擎许可证生成都成功，于是量了发行目录的真实体积。

## 他们要什么

T-02 的 DoD 第 7 条原文：

> ZIP 小于 100 MiB（GitHub 单文件上限）；确认后**留在本地 `dist/`，不 `git add`**。

问题：这一条不可能通过。实测发行目录 227.7 MiB，逐文件 deflate level 6 估算出来的 ZIP 约 **153.6 MiB**：

| 文件 | 原始 | 压缩后 |
|---|---:|---:|
| `檐下千秋.exe`（内嵌 PCK） | 231,567,256 | 158,050,097 |
| `server/yanxia-server.exe` | 7,049,216 | 3,009,230 |
| `server/content/chapters.json` | 80,463 | 13,929 |
| 三份许可 + 运行说明 | 107,188 | 30,878 |
| **合计** | **238.8 MB** | **约 153.6 MiB** |

原因不是打包方式：新版的 11 张横屏场景、水墨 UI 素材和重制的 184 段 WAV 本身已经压过，deflate 几乎压不动。v10 的 EXE 是 150.9 MB、ZIP 92.9 MiB；这一版 EXE 是 231.6 MB。

## 为什么

不改的话，T-02 的 DoD 会挂一条永远过不了的检查。执行的人要么默默跳过它，要么把「没做到」写成「做到了」。

## 影响到什么

- `docs/tasks/README.md`：T-02 的 DoD 第 7 条，旁边加一句更正（原句保留）
- 不涉及任何源码、里程碑 DoD 或其他任务行

## 代价

无。包该多大就多大，工作量和交付物不变。

## 决定

**accepted**，由 PM 决定。这不是范围变更，是一条不可能通过的检查的更正。

采用的说法：**记录真实体积，不再要求小于 100 MiB。** 理由有两条：

1. `pm-write-guard` 之前，用户已经决定这个 ZIP **不进 Git**（只在本地 `dist/`），所以 GitHub 的单文件上限对它没有约束力。
2. 实测 153.6 MiB 本来就超过 100 MiB，即使想进 Git 也推不上去——用户的决定不是偏好，是被体积逼出来的。

7 条里其余六条不变，仍然是判定 T-02 是否完成的标准。

## 新增的 DoD 条目

无。本条只更正一条不可能通过的检查，不加工作。

## Applied

- `docs/tasks/README.md`：v4（2026-09-28，`Corrections` 一节新增第二条，原句保留）
