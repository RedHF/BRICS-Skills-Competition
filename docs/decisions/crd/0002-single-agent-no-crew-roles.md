# CRD 0002：本次作业由 PM 单独执行，没有独立角色

- 编号：0002
- 日期：2026-09-15
- 作业：`repo-cleanup`

## 谁提出的

PM 提出，用户决定。PM 在确认 PRD 与任务表之后检查了自己的工具列表：本会话**没有** `crew_*` 角色工具，因此跑的不是 `crew` 预设，无法启动 `crew_engineer`、`crew_qa`、`crew_code_reviewer`、`crew_security_reviewer`、`crew_doc_reviewer` 中的任何一个。

## 想要什么

两个选择之一：

1. 用户在 `crew` 预设下新开一个会话，由真的角色跑独立 QA 与三轮评审；
2. 由本会话的 PM 单独执行全部工作，没有独立评审角色。

## 为什么

用户选择 2，理由是希望就地执行、不再多花一轮。

## 影响到什么

- `docs/tasks/` 中 T-01 的 **Verdicts** 行：`code`、`qa`、`doc` 三项只能写 `not run — <原因>`，因为它们对应的角色从来没有运行过；`security` 写 `skipped`，因为本次改动不触及网络、登录、密钥、用户输入、新依赖，只做本地文件删除。
- PRD 的「要做什么」不受影响：删什么、留什么、改哪些引用都不变。
- 里程碑 M1 的 DoD 不受影响：十四条核对仍然要逐条执行，只是执行者从独立 QA 变成 PM 本人。

## 代价

- 执行者与核对者是同一个人。一条检查写错了，没有人会从另一个角度发现它。
- 这一点必须在最终总结里如实说明，不能把 PM 自查写成「QA 通过」。

## DoD 增加项

无。

## 决定

`accepted`，决定人：用户。

## 已应用

- `docs/tasks/`：T-01 的 Verdicts 行按上述口径填写。
