# AI 协作记录留痕方案

> 适用：Task01 / Task02 / Task03 全流程 ｜ 目的：满足评分点 1.6/2.4 的"可追溯"要求 + 额外加分"70% 内容由 AI 生成"
> 配套：`docs/策划案要素填报表.md`（§5 收集留痕计划）

---

## 一、为什么要留痕（评分依据）

1. **Task01 评分点 1.6（7 分）**：AI 用于概念/机制/规则推演；**提示词、迭代与人工修订在策划案及 Original 中可追溯**，体现人机协同。
2. **Task02 评分点 2.4（4 分）**：AI 赋能美术工作流报告——流程完整（提示词策略、风格统一、筛选修图），Original 中可印证。
3. **额外加分（技术规程 §四-3）**：搭建并提交 AI 工作流文档；**作品中 70% 以上内容由 AI 工具生成**——无留痕就无法证明。
4. **综合 4.2（5 分）**：三项任务过程与成果齐全——Original 文件夹的完整度直接计分。

**一句话：评委看不到你的对话过程，只能通过你留下的痕迹评分。**

---

## 二、核心原则

| 原则 | 说明 |
|---|---|
| 真实 | 只记录真实发生的对话；**严禁事后编造提示词或截图**（评委可交叉核对，造假风险极大） |
| 即时 | 对话当场留痕（截图/导出），不要攒到最后补 |
| 完整 | 保留"提示词原文 → AI 输出 → 人工修订 → 是否回流"的完整链条，缺一环追溯力减半 |
| 双份 | 截图（图像证据）+ 记录表（结构化索引）双轨并存，互相印证 |
| 可定位 | 每条记录能对应到最终文档里的具体段落/素材（从证据到成品的"追溯链"） |

## 五、三类留痕手段（按优先级使用）

### 1. 截图存档（保底手段，全员必做）
- 每个重要对话全程截图：**提问 + AI 回答都截到**（截图工具：Win+Shift+S 区域截图，或浏览器整页截图）
- 命名：`工具_主题_序号.png`，按日期分目录存放
- 图片质量：确保文字清晰可辨（缩略图会被评委略过）

### 2. 会话导出（首选，信息最完整）
- DeepSeek / ChatGPT / Kimi 等：网页端"导出对话"或复制全文 → 存为 `工具_日期_主题.txt`
- 支持 API 的工具：保留调用日志（工具名 + 参数 + 返回）
- 绘图工具（即梦/Midjourney 等）：保存提示词、参数设置（种子、分辨率）与成图

### 3. 结构化记录表（索引层，连接证据与成品）
- 第四节的总表把上面两类原始证据组织成"时间线叙事"
- 每个任务的 AI 协作记录文档就是总表的成稿版本（见 §七）

## 六、70% AI 生成占比的量化方法

> 加分条件原文："搭建并提交 AI 工作流的工作文档，作品中 70% 以上内容由 AI 工具生成。"

| 任务 | 量化维度 | 统计口径 |
|---|---|---|
| Task01 策划案 | 按章节内容量（字数） | 逐章节标注 [AI 生成] / [AI+人工修订] / [人工撰写]，统计 AI 参与章节占总字数比例 |
| Task02 美术 | 按素材张数 | AI 生成素材张数 / 总素材张数；主场景图注明 AI 生成底图 + 人工精修 |
| Task03 代码 | 按代码行数（估算） | 注释或提交记录标注哪些模块由 AI 生成/改写/人工编写；统计行数比例 |

**建议口径**（写进 AI 协作记录文档）：AI 生成或 AI 辅助修订（AI 出初稿、人工修改后采用）均计为"AI 生成"；纯人工撰写部分单独列出。**结论控制在 70% 以上并附证据**（证据=§四记录表 + 截图 + 对比稿）。

## 七、最终交付的《AI 协作记录》文档结构（PDF/Word）

```text
一、工具与环境
   1.1 使用的 AI 工具清单（工具名 / 版本 / 账号归属人 / 使用时间段）
   1.2 各工具承担职责表
二、初始想法与创作起点
   2.1 团队最初的构思（人工想法，注明时间）
   2.2 如何将初始想法转化为 AI 提示词（转化思路示例）
三、人机互动流程（主体）
   3.1 逐轮互动记录表（§四模板，按时间排列）
   3.2 关键节点展开说明：选取 3-5 个高价值对话，附完整提示词原文 + AI 输出 + 修订前后对比
四、提示词精选
   4.1 各任务代表性提示词（策划/美术/代码各若干条，附用途说明）
   4.2 提示词迭代演进（v1 提示词 → 效果不佳 → v2 提示词 → 效果提升）
五、人工修订记录
   5.1 修订对照表（AI 产出 → 人工修改 → 终稿）
   5.2 为什么这么改（体现人机协同中的"人"）
六、产出数据与 AI 占比
   6.1 按 §六 统计的 AI 占比表
   6.2 证据索引（截图/导出文件的路径清单，指向 Original）
```

## 八、各任务留痕侧重点

| 任务 | 留什么 | 怎么证明"AI 赋能" |
|---|---|---|
| Task01 | 推演过程（概念/规则/数值）、提示词迭代 | 同一问题多轮对话：AI 给方案 → 人工指出问题 → 回流改进 |
| Task02 | 提示词策略、风格统一迭代、筛选修图 | 同一角色多版生成图 → 选中 → 精修前后对比 |
| Task03 | 代码生成、参数调整、Bug 修复 | AI 生成代码模块 → 人工测试发现问题 → AI 协助修改参数/逻辑 |

## 九、每日留痕检查清单（收工前 5 分钟）

- [ ] 今天的 AI 对话是否全部截图/导出并存到对应 `AI协作记录/` 目录？
- [ ] 互动记录总表是否追加了今天的轮次？（含提示词原文、人工修订、产出去向）
- [ ] 有产出的条目是否在最终文档/素材里能定位到？（追溯链闭合）
- [ ] 文件命名是否符合 `工具_主题_序号` 规范？
- [ ] 截图是否清晰可读？（有模糊的立即重截）

## 十、合规提醒

1. **不要编造**提示词、截图或对话记录——评分强调"可追溯"，评委可要求现场演示或核对细节。
2. AI 生成内容涉及版权风险的部分（如直接套用他人作品风格）需人工审查，README 工程约定要求"AI 生成或修改的代码必须经过人工审阅、运行验证和版权检查"。
3. 官方 IP 素材仅限参赛作品使用，原始素材路径与授权说明在 Original 中留档。
4. 个人账号、API Key 等敏感信息在提交前从所有文件中清除（README 提交前检查项）。
