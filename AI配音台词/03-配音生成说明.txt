## 二、必读：ChatTTS 会悄悄删掉你的标点

这是本次实测最有价值的发现，不处理会明显影响停顿和语气。

ChatTTS 的 `ChatTTS/norm.py` 里有一条正则：

```python
self.reject_pattern = re.compile(r"[^\u4e00-\u9fffA-Za-z，。、,\. ]")
```

在合成前，**凡是这条正则匹配不到的字符都会被静默删除**（`reject_pattern.sub("", ...)`）。
它先过一张很小的映射表，只覆盖这些：

| 原字符 | 变成 |
|---|---|
| `：` `；` | `，` |
| `！` | `。` |
| `（` `）` `【】` `『』` `「」` `《》` `－` | `，` |
| `:` `;` `!` `(` `)` `>` `<` `-` | 半角对应 |

**映射表里没有的，直接删掉。**实测本作剧本受影响情况：

| 字符 | 出现次数 | 后果 |
|---|---|---|
| `？` | 19 | 疑问句末尾标点消失 |
| `—`（破折号，共 6 对 `——`） | 12 | 停顿消失，如"两个字——平安"读成"两个字平安" |
| `‘` `’` | 各 12 | 引号消失（无害） |
| `…`（共 3 对 `……`） | 6 | 停顿消失 |
| `□` | 1 | 缺字占位符消失 |

另外 **阿拉伯数字 `0-9` 也会被删除**（`第 3 次` → `第  次`）。
本作剧本全部使用中文数字，实测 0 条受影响；但如果以后文案里出现数字，必须先转成中文。

### 本项目的处理方式

`make_slices.py` 在切片时先把这些字符换成 ChatTTS 支持、且能保住停顿的标点：

```
—— / ……  ->  ，      保留停顿
？        ->  。      至少保住句末停顿
‘ ’ “ ”  ->  删除     无害
□        ->  ，      保留缺字处的停顿
```

共改写 **46 条**。全文对照见 `切片/00-规范化对照.txt`。

## 四、方案二：批量生成

```bat
set PYTHONUTF8=1
set NO_PROXY=localhost,127.0.0.1,::1
cd C:\Users\21178\Desktop\files\chatTTS

:: 试跑 8 条
.venv\Scripts\python.exe "...\AI配音台词\工具\generate_voice.py" --limit 8

:: 只跑某个角色
.venv\Scripts\python.exe "...\AI配音台词\工具\generate_voice.py" --role 拓印师

:: 全量
.venv\Scripts\python.exe "...\AI配音台词\工具\generate_voice.py"
```

| 参数 | 说明 |
|---|---|
| `--limit N` | 只跑前 N 条 |
| `--role 名称` | 只跑某个角色 |
| `--audition N` | 生成 N 个候选声线到 `试听/`，用来挑声音 |
| `--batch N` | 每批合成条数，默认 6 |
| `--no-refine` | 跳过 refine 阶段（默认会跑，能带来更自然的停顿） |
| `--force` | 重生成已存在的文件 |
| 默认 | 已存在的文件自动跳过，**中断后可续跑** |

### 输出规格

`22050 Hz / 单声道 / 16-bit PCM`，与游戏现有 `LLM-tmp/客户端/assets/echo/` 完全一致。
ChatTTS 原始输出是 24000 Hz，脚本已用 `resample_poly` 重采样到 22050。

### 换声音的办法

每个角色固定一个声线，seed 与向量缓存在 `工具/speakers.json`：

```json
"拓印师": { "seed": 20340104, "spk_emb": "..." }
```

1. 先跑 `--audition 8`，听 `试听/候选01-seed.....wav`；
2. 挑中哪个，把该角色的 `seed` 改成那个候选的 seed，并**删掉该条目的 `spk_emb`**；
3. 重跑时脚本会用新 seed 重新采样声线；
4. 加 `--force` 重生成该角色已存在的音频。

## 五、架构注意

现有游戏是**一个事件一个 wav，内含该事件 3 句呓语**（见 `配音文本/00-索引.txt`）。
本脚本按**逐句**输出，文件名取 `manifest.csv` 的「输出音频」列，例如
`prologue_bridge_dialogue_02.wav`、`prologue_bridge_beat_01.wav`。

若要接进游戏，两种走法：

- **逐句播放**：客户端改为按顺序播放多段音频，需要改 `main.gd`；
- **拼接成组**：把同一事件的 3 句按顺序拼成一个 `prologue_bridge.wav`，
  现有代码不用改。拼接时建议句间留 250–400 ms 静音。

## 六、已知限制

- **本批音频没有人耳验收。** 脚本只能验证格式、时长、音量（非静音），
  无法判断音色是否合适、语调是否自然。必须由你实际听。
- ChatTTS 的随机声线质量不稳定，某些 seed 可能出现音色怪异或念错字。
  这也是提供 `--audition` 的原因。
- 效果最好的做法是先给主角（拓印师、檐下谱/旁白）挑好声线，再全量生成。
- 本机缺少 `pynini` / `WeTextProcessing`，ChatTTS 的中文文本正则化不可用，
  数字、特殊符号的朗读规则较弱，已在上面用预处理规避。
